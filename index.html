运输方式管理（按优先级排序）

每种运输方式有独立的"国内→FBA 时效"与"最小批次量"。算法会按"最便宜且能在到货周前到达"原则自动选方式：先按优先级从前往后匹配，命中"国内到 FBA 时效 ≤ 当周"的第一个即可；命中方式后再按其最小批次量向上取整。↑ / ↓ 可调整优先级。「是否启用」开关：停用的方式不参与备货计算、也不出现在批次下拉里（无需删除，随时可重新开启）；已排好的历史批次不受影响，重新生成方案后生效。🚚 发货模式=中转的产品，总前置期 = 国内到FBA时效 + 海外仓到FBA时效（海外仓需留出备货发货时间），并额外要求海外仓保有「海外仓保底天数 × 月均预测」的库存。🌍 区域限制（v4.12）：「区域」列标注线路适用区域（可填 美国/加拿大 等多值，用 / 分隔；空 = 通用）。产品备货只在区域匹配的线路中选择（精确相等 + 通用通配，如美国产品只能选区域=美国或通用的线路），跨区线路（如 美转加30）不会被选为常规/升舱方式。

提前释放订单（预放单）

长假/节假日（如国庆）常需要提前放单：本周把未来 1~2 周该下的订单批次也一并下出去（PO 提前下发），各批次的需求出货日期 / 预计到仓时间保持原计划不变 —— 不是把两三周的量合并成一单集中出货，只是下单动作提前。本周下单量、备货下单表会同步包含这些提前释放的批次。
释放订单周数
节假日或停摆期临时调大，放完长假后改回 1 周即可。实现方式：把未来 N-1 周该放的补货批次提前到「本周下单量」——不改各批到货节奏、不合并数量、不集中出货。所有产品统一生效（含单独配置了下单频率的产品，按各自排程周合并）。改配置后需重新点「🚀 生成备货方案」。

尾数顺延

实际备货中，缺口只有几套/几箱的小单不会单独下单，采购会顺延一两周、等缺口累积足够后一次性集中下单。尾数顺延即按此规则：本周应下单量同时低于以下两项阈值（与关系：① 周均倍数阈值 = N × 周均需求；② 绝对数量阈值，默认 30 套）且推演未来不会断货 → 本周暂不下单，缺口自动滚入后续下单周合并；若缺口接近断货风险则强制下单保不断货（不因尾数延后而断货）。顺延结果在 分析结果表（行下提示条）/ 单品详情 / 导出（末列「尾数顺延」）醒目标注，也可直接点击「本周下单量」单元格手动补单。
启用尾数顺延
关闭后恢复原行为：缺口再小也照常排本周批次
周均倍数阈值
判定条件①：缺口 < N × 周均需求。周均需求 = 方案「周均需求」列（月预测均摊口径）
绝对数量阈值（套）
判定条件②：缺口 < 该数值才视为尾数。与「周均倍数阈值」为且关系（两项同时满足才顺延）；设为 0 = 不启用该门槛（仅按倍数判定）
⚖

达成率调节

达成率低的产品，实际计划里通常要减少备货甚至不备货（预测虚高，按预测跑出来的建议量偏大）。 达成率调节把这一步交给系统：按「近四周平均周销量 ÷ 原始周均需求」算出达成率，低于阈值就给该产品一个需求系数 k， 周需求 / 安全库存 / 批次量 / 建议下单全链路都按修正后的需求计算（不是只在某一列打补丁，也不会改你导入的原始数据）。 生成方案后可在结果页「⚖ 达成率调节」清单里逐条撤销、改系数或批量恢复。
安全阀（不会误砍缺货品）：达成率低有两种原因 —— ①真的卖不动；②没货可卖（断货 / 上架慢）。 第 ② 种砍备货会雪上加霜。所以当现有可售库存不足 N 周需求、或前 M 周内出现断货时，系统判为「缺货型低达成」，不降备货，只在清单里提示。

算法说明（备货需求计算逻辑）

以下为「生成备货方案」的需求计算逻辑说明，供核对口径使用。核心链路：月度预测 → 周需求 → 到货基线 → 库存模拟 → 缺口识别 → 备货量计算 → 批次下单。
① 输入（产品级字段）
类别字段
需求月预测 M0~M5（6 个月）、预测起始月份、最新周销量 / 近四周销量（无月预测时兜底）
库存FBA库存、下架库存、海外仓库存、挪用库存
在途/在制海外仓在途（+周数）、国内在途（+周数）、在制未交（+周数）、多票导入
参数安全库存周数、生产周期(天)、计划周期(天)、备货下单频率(天)、直发比例(%)、海外仓保底天数
② 周需求展开　月度预测 → 每周需求 = 月预测 ÷ 4.33（按月内周数均摊）
情况逻辑
有预测起始月份起始月之前的周 → 需求 = 0；起始月起的周 → 按「周所在月 − 起始月」偏移取对应 fcMx，超出 6 个月用平均值
无预测起始月份从第 0 周按 所在月索引（w÷4.33）取 fcMx 展开
无月预测（全空）兜底用 实际周销量 / 近四周销量 / 最新周销量
⚠️ 前导 0 月份不得 slice 掉（会左移错位）——直接按偏移取原始值，0 预测月的周需求自然为 0。
③ 到货基线
第 0 周 = FBA库存 + 下架库存 + 海外仓库存 + 挪用库存（期初可售）；之后各周 = 海外仓在途到仓 + 国内在途到仓 + 在制未交到仓（按各自到仓周数）+ 多票在途/在制累加。
④ 库存模拟（逐周滚动）
指标公式 / 规则
期末可售期初可售 + 当周到货 − 当周需求
安全线（周级）周需求 × 安全库存周数
缺货判定可用量 < 周需求 → 缺货 = 周需求 − 可用量（期末 = 0）
预警判定期末可售 < 安全线 → 黄色预警（周次计划表显示）
⑤ 缺口扫描（按 cadence 逐轮评估，2026-09-03 v4）
每轮先做全量库存模拟（含已排补货用 prevExtraArrivals 快照，扣除下游已排避免重复计入缺口），再从全局最早可补救范围（reachFromGlobal = cadence 0 用最快方式能到货的最早周，所有 cadence 共用同一个下限，而非每轮按 cadenceOrderWeek 重算）起扫描：
firstStockout = reachFromGlobal 起首个真断货周（available < 周需求，期末 = 0）。早于 reachFromGlobal 的断货 无论本批还是更晚批次都无法挽回（不可避免历史断货），不再触发下单，避免因历史断货周永远存在而无限应急；同时 cadence N 不会再误把 cadence 0 已尽力却救不回的历史缺口重新判为"现在断货"触发升舱。
cadence 下单周 = 批序 × 频率周数（7天→0,1,2…每周一单；15天→0,2,4…；30天→0,4,8…每月一单）； 下单周 ≥ 计划期 或 常规到货周 ≥ 计划期且无断货需救 → 排单结束（不再升舱堆货）。
分档（用户三规则）：
① 常规滚动：常规方式到货周在计划期内、且不晚于首个断货周（无断货时只看能否到货）→ 用常规 35 天慢衔接，不因低安全线就升舱快运。
② 缺货能衔接（升舱）：常规到不了 / 到货晚于断货 → 升舱到最早能 ≤ 首断货周到货的方式。
③ 断货应急：连最快都救不回断货周 → fastestSub（最快方式）首批止损，后续批次接力。
⑥ 下单量（qty，2026-09-03 v4.6）
档位规则
应急档（到货周 ≥ 首断货周）qty = 到货周安全线（规则 2：不加当周需求——断货周需求已丢失，补不回已丢销量；最大即安全线，此后批次接力慢慢衔接）
衔接档（到货早于任何断货）反推 qty = 安全线 − (期初可售 − 周需求)，使「到货 + 期初 − 周需求 = 安全线」，到货后期末刚好回到安全线，不多补（规则 1/3，2026-09-03 v4.6 去普适 safetyStock/2 缓冲——之前会让每个 cadence 期末都超安全线、16 周累积过量）
到货周已 ≥ 安全线查 reachFromGlobal..到货周 之间是否仍有真断货：无 → 本 cadence 空跑推进（高库存不产生垃圾单）；有 → 补足该断货周安全线（v4.6 同步去 +safetyStock/2）
快慢分流衔接槽（v4.5 → v4.13 阶梯 / v4.14 托底线收紧）本批到货周 aw 之前若存在期末 < 该周「托底线 = 安全线 1/4 = 当周需求×safetyWeeks÷4」的薄点周 → 把缺口拆给最便宜能救回的快运方式提前到货托底（v4.13 起按 dom 降序阶梯选，非 fastestSub），剩余仍走本批方式到 aw（同一 cadence 下单周、两种运输方式）。v4.14 托底线由安全线 1/2 收紧为 1/4（原 1/2 在 safetyWeeks=4 时达 2 周需求，偏敏感）
取整/上限按单箱向上取整；safetyCeiling = max(maxBatchSize, 安全库存×2 按箱取整) 防爆（≈2×安全线口径）
⑦ 批次生成与下单
候选方式池：仅「基础数据 → 运输方式管理」中已启用的方式参与选方式与批次下拉（停用 = 临时移出候选池，无需删除；已排历史批次保留，重新生成方案后生效）。区域限制（v4.12）：候选池再按产品「区域」过滤——方式区域须与产品区域精确相等（支持 / 分隔多值），或方式标「通用/不限/空」；产品无区域则不限制。区域不匹配的线路（如美国产品对「美转加30」）不会进入常规方式解析、升舱候选、最快应急及任何批次下拉，杜绝跨区误选。
常规方式停用自动回退（2026-09-03 v4.7）：产品导入的「常规运输方式」若在管理中已被停用/改名 → 不再静默漏补（旧逻辑：库存中等无断货时 regM 匹配失败直接结束排单、期末库存跌破安全线；有断货时被迫连后续批次全走最快方式、运费高）。现自动就近回退到已启用池中的方式衔接：同档（时效相同，如 普船35→卡航35）→ 次慢档 → 最快档 → 最慢兜底；方案仍保持「常规滚动衔接 + 断货才升舱」语义，回退结果在 分析结果表（行下橙色提示条）/ 单品详情 / 导出（末列「运输方式回退」）醒目提示。
下单周 cadenceOrderWeek = 批序(batchCount) × 频率周数(orderFreqWeeks)。
到货周 = floor((下单周×7 + 生产天数 + 运输天数 + 上架天数) ÷ 7)；到货周 ≥ 计划期(weeks) 的批次不生成。
常规慢衔接（用户规则 1/3 主路径）：库存充足期不空下；一旦某 cadence 到货周将低于安全线，即下单反推量（v4.6 朴素公式，不含普适半安全线缓冲）， 常规海运逐周滚动到货衔接 —— 不会出现「一次性大额应急单 + 高价快运」（修复前：W9 出 4,960 快船22；修复后：应急首选单批最快走法不拆普船）。
升舱按阶梯选方式（v4.13 替代 v4.11 "最早到货"策略）：当 regM 救不回断货周 → 在「严格比常规快（dom < regM.dom）」的启用池中按 (dom 降序, pricePerKG 升序, 数组索引 升序) 选方式——常规 55 → 先试 35 → 救不回再 27 → 救不回再 22，避免一动就快船22（运费高）。同 dom 时按单价升序（如卡航35 4.5¥/kg 优先 普船35 5.87¥/kg）。无任何严格更快能救回 → fastestSub 兜底（实际不可达：fastestSub 到货周 ≤ firstStockout 恒成立）。
断货应急（规则 2）：首批 fastestSub、qty 封顶安全线，后续批次每轮重新评估，断货解除后自动转回常规滚动。
快慢分流衔接槽：衔接档下到货周 aw 前若出现期末低于「托底线 = 安全线 1/4 = 当周需求×safetyWeeks÷4」（v4.14 收紧，原 v4.5~v4.13 为 1/2）的薄点周，把缺口拆给「最便宜能救回的」方式（v4.13 起按阶梯选：dom 降序→price 升序，与升舱阶梯同源）+ 普船/原方式（原到货周衔接）两批；同 cadence 下单周、两种运输方式对应实际"调约一周需求走快运衔接"模式。注意：v4.13 之前衔接槽直接选 fastestSub（最快方式），现已升级到阶梯选——若仍有 ⚠ fastest 提示说明候选池里只有最快方式能在槽位到货（数学上无更便宜的中间档）。 按发货模式拆子批：直发（早到）/ 中转（dom + osToFba 晚到）/ 混合（直发比例拆分两批，浅克隆 method 对象避免跨产品共享）。
循环终止：无缺口 / 下单周 ≥ 计划期 / 常规到不了计划期且无断货需救 / 达最大迭代数。
⑧ 尾数顺延（2026-09-04 v4.8；v4.9 起双阈值且关系）
项规则
触发条件衔接档本 cadence 应下量 qty > 0，且同时满足两项阈值（且关系）：① qty < 周均倍数线（N × 周均需求，默认 1 周）；② qty < 绝对数量阈值（默认 30 套，可配 0 = 关闭该项）—— 即「低于 N 周的量」且「低于 N 套」都成立才视为尾数；且推演全程无真断货（firstStockout < 0）
动作本 cadence 不排批次，缺口滚入下一 cadence —— 库存随需求自然消耗，下轮缺口 ≈ 本轮 + 1 个下单频率窗口的需求，达到阈值后一次性集中下单（对应实际「几套先不下，过一两周再下，下单更集中」）
断货防呆存在真断货风险（firstStockout ≥ 0 / 到货周前已断货需补）→ 强制下单，尾数规则不生效 —— 顺延只用于无断货风险的场景，不会因延后而增加缺货周
不启用情形配置开关关闭；周均需求 ≤ 0（无需求产品，倍数线=0）；应急档（量=到货周安全线，恒 ≥ 阈值）；缺口 ≥ 任意启用阈值（说明缺得够多，照常下单）
醒目标注本周被顺延 → 分析结果表行下灰蓝提示条 + 单品详情头部提示条 + 导出末列「尾数顺延」（本周顺延量）；可直接点击「本周下单量」单元格手动补单
阈值在「基础数据 → 尾数顺延」可配置（开关 + 周均倍数 0.5/1/1.5/2 周 + 绝对数量阈值套数，两项为且关系）。总下单量不因顺延减少，只是把零碎小单合并为集中大单。
⑨ 提前释放订单（预放单 2026-09-08 v4.17）
项规则
配置位置「基础数据 → 提前释放订单（预放单）」下拉：1/2/3/4 周（默认 1 = 关闭，本周只放当周批）
业务场景长假/节假日（国庆）前提前放单：本周把未来 N-1 周该下的订单批次 PO 一并下出去 —— 不是把两三周的量合并成一单集中出货，各批次的需求出货日期 / 预计到仓时间保持原计划不变，只是下单动作提前
实现口径算法排程不变（各 cadence 批次的量/方式/到货周均不动）；凡「本周下单量 / 本周需下单批次」的统计、合计、编辑、导出口径从 orderWeek===0 放宽为 orderWeek < 释放周数 —— 即本次放单窗口内全部批次（含未来提前释放批）
联动视图分析结果表「本周下单量」列 / 备货下单表（Page 3）/ 备货下单表导出 / 透视表与指标卡「含本周下单量可售」/ 单品详情周次计划「本周下单量」列 —— 全部按放单窗口汇总

⑩ 达成率调节（2026-09-11 v4.26）
项规则
解决什么达成率低的产品，实际计划里要减少备货 / 不备货（预测虚高 → 按预测跑出来的建议量偏大）。过去只能系统跑完再由人工二次判断逐个改量；现在由系统按档自动给需求系数 k，一次生成即到位
达成率口径近四周平均周销量 ÷ 原始周均需求（last4WeeksSales ÷ 原始 avgWeeklyDemand）。用近四周而不是最新单周，抗单周促销/断货抖动；分母一律用未经修正的原始需求
分档与系数默认：≥80% → ×1（A 正常）；60~80% → ×0.8（B 观察）；40~60% → ×0.5（C 收缩）；<40% → ×0（D 停备，等同「售完即止」，只消耗现有库存）。阈值/系数在「基础数据 → 达成率调节」可改
作用范围k 在 planProduct 内乘到周需求上，因此周需求 / 安全库存 / 目标库存 / 最大批次量 / 尾数顺延阈值 / 缺口与批次量 / 建议下单 / 备货下单表 / 透视表全部同源生效；不改导入的原始数据，导出另附「近四周达成 / 达成率档位 / 需求系数」三列。库存可售周数、可售月数、状态判定仍用原始需求做分母（否则会被算成呆滞）
安全阀（关键）达成率低有两种原因：①真的卖不动 ②没货可卖（断货/上架慢）。第 ② 种砍备货会雪上加霜 → 当现有可售库存 < N 周需求或前 M 周内出现断货（默认 2 周 / 前 4 周）时判为「缺货型低达成」，强制 k=1 不降备货，只在清单里提示原因
撤销与追溯结果页 / 明细页头部「⚖ 达成率调节 N / 总数」胶囊 → 打开清单：逐条「🚫 不调节」或「⛔ 停备」、批量「全部恢复自动 / 全部不调节」、复制清单。撤销记在产品档案 achieveOverride（'off' 或指定系数数字），重新导入产品会覆盖
醒目标注青绿系（与橙运输回退 / 灰蓝尾数顺延 / 绿预放单 / 红数据待修 / 紫手工调整 / 蓝身份权限区分）：料品编码旁 ⚖ ×k / ⛔ 停备 / ⚖ 安全阀 角标 + 行底色 + 周均需求格小角标 + 单品详情头部提示条
数据缺失 / 0 销量「近四周销量」未导入、或「原始周均需求」为 0 → 视为数据不可判定，不参与调节（k=1）。近四周销量等于 0 时默认也不自动停备（0 销量可能是新品 / 该列没填，语义有歧义），只在清单里列出「0 销量 · 待判断」；要连 0 销量一起停，在「达成率调节 → 0 销量产品」打开开关
